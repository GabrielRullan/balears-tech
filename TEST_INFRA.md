# Test Infrastructure & Quality Architecture

## 1. Overview
The **balears.tech** quality assurance framework is built upon an automated, multi-tiered End-to-End (E2E) static analysis and acceptance test suite. It validates the build artifacts generated by Astro 5 and Tailwind CSS against all architectural, narrative, accessibility, and hosting specifications.

## 2. Architecture & File Layout
The test suite resides under the `tests/` directory and is structured in a modular, maintainable hierarchy:

```
tests/
├── test-utils.mjs     # Core assertion helpers, file system utilities, and lightweight DOM parser
├── tier1.mjs          # Tier 1: Functional Feature Inventory (105 test cases covering F1-F21)
├── tier2.mjs          # Tier 2: Boundary & Corner Cases (105 test cases covering F1-F21)
├── tier3.mjs          # Tier 3: Pairwise Interactions (21 cross-feature integration test cases)
├── tier4.mjs          # Tier 4: Realistic User Journeys (10 end-to-end user scenario test cases)
└── run-e2e.mjs        # Master runner & reporter; coordinates all tiers and emits exit codes
```

### Module Responsibilities
- **`test-utils.mjs`**:
  - Implements custom assertion primitives: `assert`, `assertEqual`, `assertMatch`, and `assertIncludes`.
  - Provides safe disk reading helpers (`readFileSafe`, `readJsonSafe`, `fileExists`).
  - Implements `parseHtml`: regex-driven semantic HTML parser extracting tags, meta tags, OpenGraph properties, headings, links, buttons, images, SVGs, IDs, and textual streams.
  - Implements `buildTestContext`: reads `dist/index.html`, `dist/_astro/*.css`, `package.json`, `firebase.json`, `.firebaserc`, and project configuration files into an immutable test context `ctx`.
- **`tier1.mjs` (`runTier1Features`)**:
  - Evaluates each of the 21 features (F1 through F21) with 5 dedicated functional tests per feature (105 total).
- **`tier2.mjs` (`runTier2Boundaries`)**:
  - Evaluates boundary conditions, negative states, security headers, anti-FOUC inline execution, image dimensions, protocol safety (zero http), and character stream offsets (105 total).
- **`tier3.mjs` (`runTier3Interactions`)**:
  - Validates cross-feature pairwise contracts: navigation links, drawer toggles, theme storage persistence, hero CTAs, and mailto generation (21 total).
- **`tier4.mjs` (`runTier4Scenarios`)**:
  - Validates 10 realistic persona journeys: citizen initiative proposal, scout trail research, developer Cloud Run inspection, non-profit pro-bono assistance, enterprise consulting exploration, mobile experience, incubator requests, executive credentials review, direct scheduling, and crawler indexing (10 total).
- **`run-e2e.mjs`**:
  - Executes all 4 tiers in sequence, aggregates results into a structured console summary table, and returns process exit code `0` on success or `1` on failure.

## 3. Test Coverage Thresholds & Criteria
- **Total Suite Size**: 241 authentic tests.
- **Passing Threshold**: 100% (241/241 passed required for production deployment).
- **Broken Link Allowance**: 0 broken external or internal anchor links.
- **Insecure Link Allowance**: 0 `http://` links (all links require HTTPS or standard protocols).
- **Character Stream Ordering**: Civic volunteering narrative (`#inici` / `#eixos`) must precede commercial consulting (`#consultoria`) by at least 10,000 bytes.
- **Layout Shift Safeguards**: 100% of `<img>` tags must specify width, height, and alt attributes.

## 4. Execution Command
```bash
# Compile Astro static build into dist/
npm run build

# Execute comprehensive 241-test acceptance runner
node tests/run-e2e.mjs
```
